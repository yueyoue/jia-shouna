## 1. 功能总览

### 1.1 衣帽间套装系统

将多件服装/鞋帽组合为「套装」（如通勤穿搭、运动套装），按场景快速查看搭配。

| 功能 | 说明 |
|------|------|
| 创建套装 | 从已有物品中选择组合，指定季节/场合 |
| 浏览套装 | 按季节/场合筛选，大封面图网格展示 |
| 编辑/删除 | 修改名称、季节、场合、关联物品 |
| 录入时关联 | 新增物品时可直接创建新套装或加入已有套装 |
| AI 自动识别 | 拍照识别物品颜色和季节，自动填入 |

### 1.2 物品借出功能

将物品借给他人，支持设置归还提醒。

| 功能 | 说明 |
|------|------|
| 借出 | 指定借出对象、数量、归还提醒天数（7/15/30/60天） |
| 归还 | 一键归还，自动恢复库存 |
| 提醒 | 到期自动推送到提醒页面「借出中」选项卡 |
| 记录 | 完整借出/归还记录，显示借出天数 |

### 1.3 物品流转日志

记录物品全生命周期操作，物品详情页底部展示。

| 操作类型 | 说明 |
|----------|------|
| `create` | 物品录入 |
| `edit` | 编辑物品信息 |
| `borrow` | 领取物品 |
| `lend` | 借出物品（含借出对象） |
| `return` | 归还物品 |

### 1.4 文件档案模块

证件、合同、票据等文件的数字化存档，记录物理存放位置。

| 功能 | 说明 |
|------|------|
| 分类管理 | 证件/合同/票据/保单/房产/车辆/教育/医疗/其他 |
| 元数据 | 证件号码、签发机构、签发日期、到期日期 |
| 照片 | 拍照扫描或相册上传文件照片 |
| 存放位置 | 记录物理位置（如：书房抽屉、保险柜） |
| 到期提醒 | 提前30天自动创建提醒 |
| 隐私控制 | 私密（仅自己）/ 共享（家庭成员可见） |

### 1.5 底部导航调整

| Tab | 顺序 | 说明 |

## 2. 数据库设计

### 2.1 outfit 表（套装）

```sql
CREATE TABLE IF NOT EXISTS `outfit` (
    `id` INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `house_id` INT UNSIGNED NOT NULL,
    `creator_id` INT UNSIGNED NOT NULL,
    `name` VARCHAR(100) NOT NULL,
    `season` VARCHAR(30) DEFAULT '',
    `occasion` VARCHAR(50) DEFAULT '',
    `cover_image` VARCHAR(500) DEFAULT '',
    `note` TEXT DEFAULT NULL,
    `status` TINYINT NOT NULL DEFAULT 1,
    `created_at` INT UNSIGNED NOT NULL,
    `updated_at` INT UNSIGNED NOT NULL,
    PRIMARY KEY (`id`),
    KEY `idx_house` (`house_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2.2 outfit_item 表（套装-物品关联）

```sql
CREATE TABLE IF NOT EXISTS `outfit_item` (

    `sort_order` INT DEFAULT 0,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_outfit_goods` (`outfit_id`, `goods_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 3. 后端 API

### 3.1 套装 API — `backend/api/outfit.php`

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `?action=create` | POST | house_id, name, season?, occasion?, note?, items[] | 创建套装 |
| `?action=list` | GET | house_id, season?, occasion?, keyword?, page? | 套装列表 |
| `?action=detail` | GET | id | 套装详情 |
| `?action=update` | POST | id, name?, season?, occasion?, note?, items[]? | 更新套装 |
| `?action=delete` | POST | id | 软删除 |

**items 格式：**
```json
[{"goods_id": 101, "slot": "top"}, {"goods_id": 102, "slot": "bottom"}]
```

**slot 值：** `top` / `bottom` / `hat` / `shoes` / `outer` / `accessory`

### 3.2 借出 API — `backend/api/goods.php`

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `?action=borrow` | POST | goods_id, quantity, note? | 领用物品 |
| `?action=lend` | POST | goods_id, quantity, lend_to, remind_days?, note? | 借出物品 |
| `?action=return` | POST | borrow_id | 归还（领用/借出通用） |
| `?action=borrowList` | GET | house_id?, goods_id? | 列出借出中记录 |
| `?action=flowLog` | GET | goods_id | 物品流转日志 |

**lend 请求示例：**
```json
{
    "goods_id": 101,
    "quantity": 1,
    "lend_to": "张三",
    "remind_days": 30,
    "note": "春节聚会借的"
}
```

**lend 后端逻辑：**
1. 校验库存 ≥ quantity
2. 插入 `goods_borrow`（status=1, lend_to, remind_at=now+remind_days*86400）
3. 扣减 goods.quantity
4. 写入 `goods_log`（action='lend'）
5. 如果 remind_days > 0，创建 reminder（type='lend_return'）

**return 后端逻辑：**
1. 查 goods_borrow（status=1）
2. 更新 status=2, return_time=now
3. 恢复 goods.quantity
4. 写入 `goods_log`（action='return'）

### 3.3 文件档案 API — `backend/api/document.php`

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `?action=list` | GET | house_id, category?, keyword?, expiring?, page? | 列表 |
| `?action=detail` | GET | id | 详情（含图片） |
| `?action=create` | POST | house_id, name, category, doc_no?, issuer?, issue_date?, expiry_date?, storage_location?, note?, is_private?, images[]? | 创建 |
| `?action=update` | POST | id, ... | 更新 |
| `?action=delete` | POST | id | 软删除 |
| `?action=stats` | GET | house_id | 统计（总数/各分类/即将过期/已过期） |

**过期状态自动计算：**
- `expired`: expiry_date < 今天
- `expiring`: 0-30天内到期
- `warning`: 30-90天内到期
- `valid`: 90天以上

### 3.4 提醒 API 扩展 — `backend/api/reminder.php`

`?action=list` 新增自动生成的借出到期提醒：

```php
// 自动查询 goods_borrow 中 lend_to 不为空、remind_at <= 明天 的记录
// 生成 type='lend_return' 的提醒项
```

提醒类型优先级：expiry(0) → lend_return(1) → low_stock(2) → custom(3)

### 3.5 图片上传 — `backend/api/upload.php`

```
POST /api/upload.php?action=image
Content-Type: multipart/form-data
字段: file (图片文件)
```

**照片压缩策略：**
```java
// 拍照/AI拍照/相册 三条路径统一：
bitmap = fixPhotoOrientation(uri, bitmap);  // EXIF方向修正
bitmap = resizeBitmap(bitmap, 1600);         // 最大1600px
bitmap.compress(JPEG, 80, baos);             // 80%质量
// 结果通常 200-500KB，远小于后端 2MB 限制
```

**EXIF 方向修正：**
```java
private Bitmap fixPhotoOrientation(Uri uri, Bitmap bitmap) {
    InputStream is = getContentResolver().openInputStream(uri);
    ExifInterface exif = new ExifInterface(is);
    int orientation = exif.getAttributeInt(TAG_ORIENTATION, ORIENTATION_NORMAL);
    // ORIENTATION_ROTATE_90 → 90°, 180 → 180°, 270 → 270°
    Matrix matrix = new Matrix();
    matrix.postRotate(degrees);
    return Bitmap.createBitmap(bitmap, 0, 0, w, h, matrix, true);
}
```

## 7. 已修复的问题

### 7.1 套装关联丢失

**问题**：物品通过拍照/相册录入时，选择新建套装后保存，物品未加入套装。

**原因**：`createGoodsWithImages()` 的 onSuccess 回调中缺少 `pendingOutfitId` 检查。只有无照片的 `doSave()` 路径有关联逻辑。

**修复**：在 `createGoodsWithImages()` 的 onSuccess 中加入：
```java
if (pendingOutfitId > 0 && !isEditMode) {
    int goodsId = data.get("id").getAsInt();
    if (goodsId > 0) addItemToOutfit(pendingOutfitId, goodsId);
}
```

### 7.2 AI 识别 2MB 限制

**问题**：从相册选取照片进行 AI 识别时提示「图片大小不能超过 2MB」。

**原因**：相册照片直接以原始尺寸发送，未压缩。拍照路径有 resizeBitmap(1600) + 80% JPEG 压缩。

**修复**：相册路径统一压缩策略：
```java
Bitmap compressed = resizeBitmap(bitmap, 1600);
addPhotoToList(compressed);
compressed.compress(Bitmap.CompressFormat.JPEG, 80, baos);
callAiRecognize(baos.toByteArray());
```

### 7.3 照片方向错误

**问题**：手机拍照后照片横着显示。

**原因**：相机传感器以横向拍摄，EXIF 方向信息在 Bitmap 加载时丢失。

**修复**：新增 `fixPhotoOrientation()` 方法，读取 EXIF orientation tag，通过 Matrix 旋转修正。三条路径（拍照/AI拍照/相册）均应用。

### 7.4 底部导航崩溃

**问题**：添加「提醒」Tab 后 APP 启动崩溃，报 `InflateException: Error inflating BottomNavigationView`。

**原因**：`BottomNavigationView` 最多支持 5 个项目。超过 5 项在部分设备（API 28+）上直接抛异常。

**修复**：移除底部导航的「扫码」Tab（首页已有扫码入口），保留 5 项。同时将提醒图标从系统 `ic_menu_recent_history`（部分设备不存在）改为自定义 `drawable/ic_nav_reminders.png`。
