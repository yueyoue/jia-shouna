## 1. 项目概述

### 1.1 产品定位

「家收纳」是一款面向家庭用户的物品全生命周期管理工具，解决家庭物品**找不到、记不住、易过期、重复买**的痛点。

### 1.2 核心功能一览

| 模块 | 功能 |
|------|------|
| 收纳空间 | 多房屋 → 房间 → 容器 三级层级管理，支持图标/颜色自定义 |
| 物品管理 | 录入（条码/拍照/AI/手动）、搜索、领用归还、批量导入导出 |
| AI智能识别 | 拍照自动识别物品名称、品牌、条码、保质期、推荐分类 |
| 智能提醒 | 临期物品提醒（动态规则）、库存不足提醒、自定义提醒 |
| 家庭协作 | 多成员共享、邀请码加入、角色权限（管理员/编辑/只读） |
| 隐私控制 | 物品级隐私设置，仅自己可见 |
| 离线支持 | 无网络时可查看已缓存的物品数据 |
| 数据统计 | 分类统计、空间统计、成员贡献排行 |
| 日志监控 | APP端崩溃/错误自动上报，管理后台实时查看 |
| 版本管理 | APP自动更新检查，支持强制更新 |

### 1.3 技术栈

| 端 | 技术 |
|---|---|
| APP端 | Android 原生 (Java, minSdk 26, targetSdk 34) |
| 后端 | PHP 7.4+ / 8.0+ |
| 数据库 | MySQL 5.7+ / 8.0+ |
| 管理后台 | PHP + HTML + CSS + JS（无框架，纯原生） |
| 构建 | GitHub Actions 自动编译 + 自动发布 Release |
| 依赖库 | OkHttp 4.12 / Gson 2.10 / Glide 4.16 / ZXing 3.5 / Material 1.11 |

### 3.3 物品录入 (AddItemActivity)

这是 APP 最核心的页面，顶部有 4 个 Tab 切换不同录入方式：

**Tab 结构：**

| Tab | 图标 | 功能 | 交互流程 |
|-----|------|------|---------|
| 📷 扫码 | 相机 | 条码扫描 | 调用 ZXing 扫码 → 自动查询条码信息 → 填入表单 |
| 📸 拍照 | 图片 | 拍照录入 | 拍照添加物品图片，不自动识别 |
| ✏️ 手动 | 编辑 | 手动录入 | 纯手动填写表单 |
| 🤖 AI | 机器人 | AI识别 | 拍照 → AI自动识别 → 结果填入表单 |

**表单字段（所有 Tab 共用同一个表单）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 存放位置 | 三级联动选择器 | ✅ | 家 → 房间 → 容器，逐级选择 |
| 物品名称 | 文本输入 | ✅ | 物品名称 |
| 条形码 | 文本输入 | - | 扫码或手动输入，有扫码按钮 |
| 品牌 | 文本输入 | - | AI识别或手动输入 |
| 生产厂商 | 文本输入 | - | 条码查询自动填入 |
| 规格 | 文本输入 | - | 如 "0.4g*24粒" |
| 数量 | 数字输入 | - | 默认1，支持 +/- 按钮 |
| 单位 | 下拉选择器 | - | 个/盒/瓶/包/袋/罐/箱/件/套 |
| 生产日期 | 日期选择器 | - | 点击弹出日期选择 |
| 保质期 | 数字+单位 | - | 天/月/年，自动计算过期日期 |
| 过期日期 | 自动计算 | - | 根据生产日期+保质期计算，也可手动选择 |
| 购买价格 | 数字输入 | - | 可选 |
| 库存阈值 | 数字输入 | - | 低于此值触发库存不足提醒 |
| 物品标签 | 多选标签 | - | 从已有标签选择或新建，支持删除 |
| 物品照片 | 图片列表 | - | 拍照添加，支持左右滑动查看、删除 |
| 隐私设置 | 开关 | - | 仅自己可见 |
| 备注 | 多行文本 | - | 备注信息 |

**AI 识别详细流程：**
1. 点击"AI识别"Tab → 调起系统相机拍照
2. 图片压缩（JPEG 85%）上传到 `ai/recognize.php`
3. 显示 Toast "AI 正在识别..."
4. AI Agent 自动调度：多模态大模型识别 → 条码查询 → 空间推荐
5. 返回识别结果（名称、品牌、条码、规格、分类、保质期、置信度、推荐存放位置）
6. 用户确认后自动填入表单，分类自动添加为标签，照片自动添加到物品图片

## 7. AI智能识别系统

### 7.1 架构概述

采用 **大模型函数调用（Function Calling）** 实现轻量 AI Agent，无需引入重型 Agent 框架。

```
用户拍照 → APP上传图片 → 后端接收
                              │
                    ┌─────────▼─────────┐
                    │   AI Agent 调度    │
                    │  (Agent.php)       │
                    └─────────┬─────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
    ┌─────────────┐  ┌──────────────┐  ┌──────────────┐
    │ 多模态大模型  │  │ 条码查询工具  │  │ 空间推荐工具  │
    │ (GLM-4V等)  │  │ BarcodeTool  │  │ SpacesTool   │
    └─────────────┘  └──────────────┘  └──────────────┘
                              │
                    ┌─────────▼─────────┐
                    │  结构化 JSON 结果   │
                    │  → 填入 APP 表单    │
                    └───────────────────┘
```

### 7.2 支持的AI服务商

| 服务商 | 模型 | 核心能力 | 成本 |
|--------|------|---------|------|
| 智谱 GLM-4V-Flash | glm-4v-flash | 多模态识图 + Function Calling | 永久免费额度 |
| 火山引擎 豆包 | doubao-vision-pro-32k | 商品包装识别精度高 | 新用户赠送 |
| 百度文心 | ernie-speed-128k | 日用品/药品包装文字识别 | 新用户免费 |

### 7.3 AI工具集

| 工具名 | 功能 | 输入 | 输出 |
|-------|------|------|------|
| lookup_barcode | 条码查询 | barcode | 商品信息/未找到 |
| match_goods | 商品匹配 | goods_name, house_id | 匹配列表 |
| get_storage_spaces | 空间推荐 | house_id | 空间树形结构 |

### 7.4 识别流程

1. 用户拍照上传图片
2. Agent 注册所有工具，调用多模态大模型
3. 大模型从图片中识别条码和包装文字
4. 有条码 → 调用 lookup_barcode 查询商品信息
5. 调用 get_storage_spaces 获取空间列表，推荐存放位置
6. 汇总结果，返回结构化 JSON
7. 最多 3 轮工具调用循环，防止死循环

## 8. 离线功能

### 8.1 设计方案

采用**只读缓存**方案：
- 联网时自动缓存物品列表到本地 SQLite
- 离线时从缓存加载，只读不可编辑
- 图片不缓存（只存 URL），不占额外空间
- 缓存容量约 1MB / 1000 件物品

### 8.2 本地数据库

**数据库名**：`jiashouna_local.db`

**缓存表**：`cache_goods`（存储物品列表快照）

**离线创建表**：`local_goods`（存储断网时创建的物品，联网后同步）

### 8.3 离线行为

| 功能 | 离线可用 | 说明 |

## 9. 日志与监控系统

### 9.1 APP端日志收集

**初始化**：`App.onCreate()` 中调用 `AppLogger.init(this)`

**能力：**
- 全局未处理异常捕获（UncaughtExceptionHandler）
- crash 日志同步上报（确保崩溃前数据发出）
- error/warn/info 日志缓冲上报（满5条自动上传）
- API 错误记录

**日志数据：** type / tag / message / stack_trace / device_info / app_version / user_id

### 9.2 智能提醒系统

**提醒类型：**
- **临期提醒**：根据保质期时长动态匹配提醒规则（见 3.7 节）
- **库存不足提醒**：当物品数量 ≤ 库存阈值时触发
- **自定义提醒**：用户手动创建的提醒

### 11.2 APP 端设计要素

- **底部导航**：5 Tab（首页/空间/扫码/提醒/我的）
- **卡片风格**：圆角 16dp，轻微阴影
- **字体层次**：标题 24sp / 正文 14sp / 辅助 12sp
- **图标风格**：emoji 作为空间/分类图标
- **列表项**：左侧图片/emoji + 右侧信息 + 右侧操作

### 11.3 Web 管理后台设计要素

- **侧边栏**：固定左侧，分组导航，当前页高亮
- **卡片**：圆角 var(--radius)，边框 1px solid var(--border-2)
- **表格**：斑马纹，hover 高亮
- **弹窗**：模态弹窗，表单编辑
- **响应式**：移动端侧边栏折叠

### 11.4 UI 设计师重点关注

以下页面是面向用户的核心界面，建议重点设计：

**APP 端（优先级从高到低）：**
1. **首页 (HomeFragment)** — 用户每天看到的第一个页面
2. **物品录入 (AddItemActivity)** — 核心交互页面，4种录入方式
3. **物品详情 (ItemDetailActivity)** — 信息展示 + 操作
4. **空间列表 (SpacesFragment)** — 层级结构展示
5. **提醒列表 (RemindersFragment)** — 多类型提醒混合展示
6. **我的 (ProfileFragment)** — 个人信息 + 设置入口
7. **登录/注册** — 第一印象

**Web 管理后台：**
1. **数据看板 (dashboard)** — 信息密度最高的页面
2. **物品管理 (items)** — 列表 + 筛选 + 弹窗编辑
3. **收纳空间 (spaces)** — 树形结构 + 详情联动
4. **系统设置 (settings)** — 表单布局
